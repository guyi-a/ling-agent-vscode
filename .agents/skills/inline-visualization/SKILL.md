# 对话内联可视化

把适合图示的内容画成**在对话里直接渲染出来的图**，而不是让用户读一长串文字或自己想象。

## 输出格式（唯一的硬约定）

先给一句结论，然后输出一个把语言标成 `html`、并把 `type="renderer"` 写进围栏信息的代码块：

````
结论：读路径是 请求 → 校验 → 缓存 → 落库。

```html type="renderer"
<svg viewBox="0 0 600 160" xmlns="http://www.w3.org/2000/svg">
  ...
</svg>
```
````

**只有带 `type="renderer"` 的围栏会被渲染成图。** 不加这个标记就是普通代码块，用户看到的是源码。反过来，如果你确实想让用户看到源码，就不要加这个标记。

## 不使用本 skill

- 简短事实、确认、翻译、闲聊 —— 文字足够清楚时不要画图
- **数值图表**（折线 / 柱状 / 饼图 / 散点）：当前没有图表库，画不了；这类内容用表格或文字
- 海报、头像、写实插画、艺术创作
- 地图、地理轨迹

## 硬规则

**静态优先。** 图里不要写脚本，也不要做动画。当前渲染环境**不执行脚本**，写了不仅无效，还可能让整块渲染失败。

**必须自包含。** 不允许任何外部资源：
- 不要 `<script src="...">`、不要 CDN
- 不要外部图片 / 字体（`<img src="https://...">`、`url(https://...)` 会被剥掉）
- 需要图片时用内联 SVG 画，或用 CSS 渐变 / 形状

**不依赖交互。** 核心结论必须在**初始静态状态**下就看得懂 —— 不要设计成「悬停才显示详情」或「点击展开」。

**数据可复核。** 真实数字、名称、术语只来自用户材料或工具结果。**示例数据要显式标注**（例如标题里写「示意」）。

**一个图只讲一件事。** 默认只输出一个图块。确实需要第二个时才加，最多两块。

**失败可降级。** 结构或事实不足以可靠绘制时，改用文字或表格，不要硬画一张含糊的图 —— 一张错误的图比没有图更糟。

## 怎么画

优先用 **SVG** 画结构（流程图、架构图、时间线、状态机、层级树），用 **HTML + CSS** 画卡片式版面（对比、清单、要点归纳）。

布局要点：

- SVG 一定要写 `viewBox`，宽度交给外层自适应；`width="100%"` 但**不要写死 `height`**
- 文字用 `font-family="inherit"` 或直接继承，不要指定具体字体名
- 留出内边距，不要让元素贴着边框
- 连线用 `stroke`，不要用 `border` 拼

避免这些常见问题：

- 文字溢出容器（估算文本宽度时留足余量；中文按 1 字 ≈ 1 em 估）
- 深浅色模式下看不清（颜色规则见下）
- 元素重叠、连线穿过文字

## 颜色与主题

**结论：在 Codex 里画图，颜色必须自带，不能只依赖主题变量。**

Codex 的对话内渲染环境**并不定义**下面这组变量。`fill="var(--text)"` 会解析成无效值，SVG 于是回退到属性初始值（`fill` 的初始值是黑色），最终黑底黑字、整块图什么都看不见。这个坑已经踩过一次，用户看到的就是几个纯黑的方块。

正确做法，按优先级：

1. **给每个形状自己带颜色。** 深色卡片底 + 浅色文字，自带对比度，切主题都不受影响。推荐一组：

   | 用途 | 值 |
   | --- | --- |
   | 面 / 卡片背景 | `#242c3b` |
   | 正文 | `#e9edf5` |
   | 次要文字 | `#98a3b8` |
   | 边框、连线、次要标注 | `#3b465a` / `#7d8899` |
   | 成功 / 304 | 底 `#16301f`、描边 `#3f9e6a`、字 `#6ee7a8` |
   | 信息 / 200 | 底 `#16233d`、描边 `#3b6fd4`、字 `#8ab4ff` |

2. **确实要跟随主题时，必须给兜底值**：写 `var(--text, #e9edf5)` 而不是 `var(--text)`。变量缺失也能看见。

3. **纯文字排版（HTML + CSS 卡片）不要设 `color`**，让它继承容器文字色，天然安全。

关于深色底图在浅色主题下的观感：深色卡片无论放在哪种主题背景上都读得清，代价只是"看起来像一张深色卡片"，这个代价可以接受；文字被渲染成黑色才是真正的失败。所以**优先保证可读，其次才是贴合主题**。

字号遵循应用的阶梯，只用这几档：**10 / 11 / 12 / 13 / 14 / 16 / 18px**。正文用 14px，标题 16 或 18px，标注 11 或 12px。

圆角：SVG 里 `rx` 直接写数字（`rx="8"`），不要写 `var(--radius-md)`——同理，变量可能不存在。HTML + CSS 里可以用 `var(--radius-md, 8px)`。

## 平时不要自检，出问题再排查

**改完图直接发。** 不要为了"保险"去跑本地渲染——用户会直接反馈图好不好看，多跑一轮纯属浪费时间。

只有当用户说「看不见 / 看不清 / 文字被裁 / 布局错乱」时，才把图渲染出来看一眼：

```powershell
& "C:\Program Files\Google\Chrome\Application\chrome.exe" --headless=new --disable-gpu --no-sandbox `
  --user-data-dir="<临时目录>" --window-size=800,490 --screenshot="<输出>.png" "file:///<svg 路径>"
```

Chrome 的 crashpad / mojo 在 Codex 沙箱里会被拒绝、起不来，这一步需要申请一次免沙箱执行；截完把临时 profile 目录删掉。

## 自检清单（输出前过一遍）

- 这张图是否真的比文字更好懂？如果只是把文字换个排列，就别画
- 颜色是否自带、或每个 `var()` 都带兜底值？（只写 `var(--x)` 会变黑，渲染环境不定义这些变量）
- 是否完全没有脚本和外部资源？
- 初始状态（不悬停、不点击）能否看懂？
- 窄屏下会不会溢出、文字会不会被裁？
- 示例数据是否标注了「示意」？
